## PDF

### `pdf.white_text` White-on-white text

Payload drawn in white on a white page.

- **Why parsers miss it:** Text extractors return glyphs regardless of fill colour.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Drop text whose fill colour matches the background; compare against a rendered-page OCR.

### `pdf.tiny_font` Microscopic font

Payload drawn at 0.5pt.

- **Why parsers miss it:** Font size is ignored during extraction.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Drop text below a minimum rendered size (e.g. 4pt).

### `pdf.render_mode_3` Invisible render mode

Text render mode 3 (no fill, no stroke).

- **Why parsers miss it:** Render mode 3 paints nothing, but the text operators remain in the content stream.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Skip text with render mode 3 or 7.

### `pdf.off_page` Off-page coordinates

Payload placed outside the MediaBox.

- **Why parsers miss it:** Extractors read every text object, including ones outside the MediaBox/CropBox.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, markitdown
- **Not leaked by:** pdftotext
- **Mitigation:** Clip extracted text to the visible page box.

### `pdf.covered` Covered by shape

Payload drawn, then painted over by an opaque rectangle.

- **Why parsers miss it:** Extractors do not model z-order, so text painted over by a later shape survives.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Render-based extraction (OCR or layout models that reason over pixels).

### `pdf.clipped` Clipped away

Payload drawn inside a 1x1pt clipping path.

- **Why parsers miss it:** Clipping paths are graphics state, which text extraction ignores.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Apply the clip path, or use render-based extraction.

### `pdf.alpha_zero` Zero opacity

Payload drawn with fill alpha 0.

- **Why parsers miss it:** Opacity lives in the ExtGState and is ignored by extractors.
- **Leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Drop text with fill alpha 0, or use render-based extraction.

### `pdf.metadata` Document metadata

Payload in Subject/Keywords info fields.

- **Why parsers miss it:** Loaders that attach document info (Title/Subject/Keywords) to chunks pass it to the model.
- **Leaked by:** pypdf+metadata
- **Not leaked by:** pypdf, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Mitigation:** Never put document metadata into the prompt unlabelled; treat it as untrusted.

### `pdf.annotation` Zero-size annotation

Payload in a zero-area text annotation.

- **Why parsers miss it:** Annotation contents are a separate object; mainstream extractors skip them.
- **Leaked by:** none of the built-in parsers
- **Not leaked by:** pypdf, pypdf+metadata, pdfplumber, pdfminer.six, pdftotext, markitdown
- **Mitigation:** Keep it that way; if you add annotations, label them as such.

## DOCX

### `docx.hidden_run` Hidden run (w:vanish)

Payload in a run with the Word 'hidden' property.

- **Why parsers miss it:** Word's hidden-text property (w:vanish) is formatting; text APIs ignore it.
- **Leaked by:** markitdown, python-docx, python-docx+metadata, libreoffice-txt
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Skip runs with w:vanish / font.hidden.

- **Why parsers miss it:** Run colour is formatting.
- **Leaked by:** markitdown, python-docx, python-docx+metadata, libreoffice-txt
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Flag runs whose colour matches the page/shading.

### `docx.tiny_font` 1pt font

Payload at 1pt.

- **Why parsers miss it:** Run size is formatting.
- **Leaked by:** markitdown, python-docx, python-docx+metadata, libreoffice-txt
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Flag runs below a minimum size.

### `docx.core_properties` Core properties

Payload in keywords/comments metadata.

- **Why parsers miss it:** Metadata loaders include keywords/comments.
- **Leaked by:** python-docx+metadata
- **Not leaked by:** markitdown, python-docx, libreoffice-txt
- **Mitigation:** Treat core properties as untrusted, or drop them.

### `docx.unicode_tags` Unicode tag smuggling

Payload encoded as invisible U+E00xx tag characters.

- **Why parsers miss it:** U+E0000 tag characters render as nothing but survive text extraction, and many tokenizers read them.
- **Leaked by:** markitdown, python-docx, python-docx+metadata, libreoffice-txt
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Strip the Unicode tag block (U+E0000-E007F) and other invisible code points before prompting.

## XLSX

### `xlsx.hidden_sheet` Hidden worksheet

Payload on a sheet with state=hidden.

- **Why parsers miss it:** Workbook readers iterate all worksheets, whatever their state.
- **Leaked by:** markitdown, openpyxl (all cells)
- **Not leaked by:** openpyxl (visible only), openpyxl (comments)
- **Mitigation:** Skip sheets whose state is not 'visible'.

### `xlsx.very_hidden_sheet` Very hidden worksheet

Payload on a sheet with state=veryHidden (cannot be unhidden from Excel's UI).

- **Why parsers miss it:** 'veryHidden' sheets cannot be unhidden from Excel's UI, so reviewers will not find them, but readers still load them.
- **Leaked by:** markitdown, openpyxl (all cells)
- **Not leaked by:** openpyxl (visible only), openpyxl (comments)
- **Mitigation:** Skip non-visible sheets; alert on veryHidden ones.

### `xlsx.hidden_row` Hidden row

Payload in a hidden row.

- **Why parsers miss it:** Row visibility is a dimension attribute that cell iterators ignore.
- **Leaked by:** markitdown, openpyxl (all cells)
- **Not leaked by:** openpyxl (visible only), openpyxl (comments)
- **Mitigation:** Skip hidden rows.

### `xlsx.hidden_column` Hidden column

Payload in a hidden column.

- **Why parsers miss it:** Column visibility is a dimension attribute that cell iterators ignore.
- **Leaked by:** markitdown, openpyxl (all cells)
- **Not leaked by:** openpyxl (visible only), openpyxl (comments)
- **Mitigation:** Skip hidden columns.

### `xlsx.white_text` White text

Payload in a white-font cell.

- **Why parsers miss it:** Cell font colour is formatting. Even 'visible-only' loaders pass it.
- **Leaked by:** markitdown, openpyxl (all cells), openpyxl (visible only)
- **Not leaked by:** openpyxl (comments)
- **Mitigation:** Flag cells whose font colour matches the fill.

### `xlsx.cell_comment` Cell comment

Payload in a cell comment (not printed).

- **Why parsers miss it:** Comments are not printed, but comment-aware loaders include them.
- **Leaked by:** openpyxl (comments)
- **Not leaked by:** markitdown, openpyxl (all cells), openpyxl (visible only)
- **Mitigation:** Label comments as such, or exclude them.

## HTML

### `html.display_none` display:none

Payload in an element with display:none.

- **Why parsers miss it:** HTML-to-text converters do not evaluate CSS.
- **Leaked by:** markitdown, bs4.get_text, bs4 (strip script/style), raw-html
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Extract from a rendered DOM (innerText in a real browser), not raw markup.

### `html.font_size_zero` font-size:0

Payload with zero font size.

- **Why parsers miss it:** Inline styles are ignored.
- **Leaked by:** markitdown, bs4.get_text, bs4 (strip script/style), raw-html
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Extract from the rendered DOM.

### `html.color_match` Colour-matched text

White text on white background.

- **Why parsers miss it:** Inline styles are ignored.
- **Leaked by:** markitdown, bs4.get_text, bs4 (strip script/style), raw-html
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Extract from the rendered DOM and compare colour with the background.

### `html.offscreen` Off-screen positioning

Absolutely positioned at left:-9999px.

- **Why parsers miss it:** Positioning is ignored.
- **Leaked by:** markitdown, bs4.get_text, bs4 (strip script/style), raw-html
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Extract from the rendered DOM and drop elements outside the viewport.

### `html.comment` HTML comment

Payload inside <!-- -->.

- **Why parsers miss it:** Only raw-source readers (agents that fetch page source) see comments.
- **Leaked by:** raw-html
- **Not leaked by:** markitdown, bs4.get_text, bs4 (strip script/style)
- **Mitigation:** Never put raw HTML into the prompt; convert it first.

### `html.img_alt` Image alt text

Payload as alt text of a 1x1 image.

- **Why parsers miss it:** Markdown converters keep alt text, which a sighted user does not see.
- **Leaked by:** markitdown, raw-html
- **Not leaked by:** bs4.get_text, bs4 (strip script/style)
- **Mitigation:** Label alt text, or drop it for untrusted pages.

### `html.aria_label` aria-label attribute

Payload in an aria-label on an empty span.

- **Why parsers miss it:** Only raw-source readers see attributes.
- **Leaked by:** raw-html
- **Not leaked by:** markitdown, bs4.get_text, bs4 (strip script/style)
- **Mitigation:** Convert HTML before prompting; treat accessibility attributes as untrusted.

### `html.unicode_tags` Unicode tag smuggling

Payload as invisible tag characters.

- **Why parsers miss it:** Invisible tag characters survive HTML-to-text conversion.
- **Leaked by:** markitdown, bs4.get_text, bs4 (strip script/style), raw-html
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Strip the Unicode tag block and other invisible code points.

## EML

### `eml.plain_html_mismatch` text/plain vs text/html mismatch

Client shows the HTML part; the plain-text alternative carries the payload.

- **Why parsers miss it:** Mail clients show text/html; many pipelines prefer text/plain. The two alternatives need not agree.
- **Leaked by:** email (plain preferred), email (all parts+headers)
- **Not leaked by:** email (html preferred)
- **Mitigation:** Use the same part the user sees (HTML, rendered), or flag messages whose alternatives disagree.

### `eml.html_display_none` Hidden HTML in email

display:none payload in the HTML body.

- **Why parsers miss it:** Same as HTML: converters ignore CSS.
- **Leaked by:** email (plain preferred), email (html preferred), email (all parts+headers)
- **Not leaked by:** none: every tested parser leaked it
- **Mitigation:** Extract from rendered HTML.

### `eml.custom_header` Custom X- header

Payload in a non-displayed X- header.

- **Why parsers miss it:** 'Dump the whole message' pipelines include every header.
- **Leaked by:** email (all parts+headers)
- **Not leaked by:** email (plain preferred), email (html preferred)
- **Mitigation:** Only pass From/To/Subject/Date; treat all headers as untrusted.
